# 0007: オフライン入力は送信待ちキューで同期する

## 決定

オフライン時の操作は端末の送信待ちキュー(localStorage)に保存し、接続回復時に順に送信する。サーバ側のAPIは冪等に設計し、競合の解決規則は持たない。

## 理由

- 食事記録は利用者ごとに独立し、他の端末と同じ記録を同時に編集することはまれ
- 追加は`clientRef`による重複防止, 変更・体重は上書き, 削除は削除済みを成功とすれば、再送しても結果が変わらない
- IndexedDBや同期専用APIを導入するより構成が単純

## 制約

- 送信待ちは端末・ブラウザ単位で、ログアウトしても利用者ごとに保持する
- コピー・再計算などサーバでの計算が必要な操作はオンライン時のみ
